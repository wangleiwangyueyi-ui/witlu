# P3 · 海洋与晴空环境

P3 的 A1–A5 已接入主程序，先在 /lab/ocean 和 /lab/clouds 验证，再完成三种视口的连续录屏、FPS 与像素审计。主程序加 ?debug=1 可检查九个环境开关和实际预算。

## 完成项

- y=0 海面覆盖东海、南海、印度洋和太平洋；基于真实海底深度的三段夜蓝色、双层滚动法线、冷色月光反光与菲涅尔。沿用 PLAN 色板，通过曝光控制保持 L0。
- 构建期 Natural Earth 离岸距离场、向岸推进并消散的淡蓝光浪；黑潮和南海环流的缓慢实例化流线。
- 晴空渐变球、远景雾、180 秒往复 ±15° 光照；地形明暗和云影方向共享太阳参数。
- 柔边实例化云，每 45 秒进入一或两团；共享覆盖纹理投出很淡的移动云影；拉近同步渐隐。全部云层完全重叠时也不超过 35% 透明度。
- 极致 / 高 / 省电、九个独立开关、系统与站内减少动态、隐藏页面暂停、上下文恢复；无逐帧 React 重渲染。
- 环境资源构建、SHA 校验、断点复用和部署文档；环境数值纹理约 722.1 KiB，构建生成，不提交瓦片或 CHGIS 衍生数据。

原理、参数与复验命令见 [ENVIRONMENT.md](../ENVIRONMENT.md)。

## L0 与真实动效审计

直接读取 WebGL 合成画面，排除界面白字，在海洋和云层场景共检查 2,592,000 像素。最大显示亮度跨度 24.15 个百分点（上限 25），白字最低对比度 7.46:1，非 B>G>R 像素 0。[原始审计](performance/P3/l0-audit.json)。

固定相机、时刻和其他开关，分别验证水面、岸浪与云影输出，不只检查“开关为真”：水面 5,023 像素、岸浪 14,957 像素、云影 4,366 像素发生 ≥3 个 RGB 字节总差异。[逐项数据](performance/P3/pixel-proof.json) · [无云影](screenshots/P3/shadow-off.png) · [有云影](screenshots/P3/shadow-on.png)。

截图中标题、卡片和时间轴优先于海与云。真实彩色政权覆盖层属于 P4，**“版图优先”的完整叠加验收需在 P4 再做**，本阶段没有伪造边界覆盖来声称它已完成。

- pnpm test:environment：三视口 ≥50fps 与 32 秒连续记录、独立像素变化和 L0 合成审计，共 5 项通过、4 项不适用手机的重复像素审计跳过。
- pnpm build：完整 assets / data / tiles / typecheck / Vite 生产构建通过。全部 JS/CSS 分块 gzip 合计 272.4 KiB；这是构建资产总量，不是首屏网络实测。
- 浏览器验证四海域、九开关、画质预算、系统减少动态即时响应、WebGL 丢失恢复。单元测试覆盖精确距离变换对照、入岸波向、云出生节律 / 透明度、近景渐隐、光照周期和降级规则。

## 偏差、未完成项与已知问题

1. 离岸场为 z6 全域计算后 2×降采样，供 L0 光浪使用；不是逐 z3–8 的独立距离瓦片。避免跨瓦片波相接缝，运行时增加约 15MiB RGBA 图集。海岸形状受 Natural Earth 50m 和取样精度限制。
2. 海水在 PLAN 色板基础上降低环境曝光；云与流线也限制合成亮度，避免覆盖雪峰后破坏文字对比度。云为全国尺度的艺术表达，非真实气象高度。
3. 光照采用高程法线的动态晕渲和纹理云影，不生成整片地形实时投射阴影贴图。省电关闭岸浪、洋流和云影，保留单层海水法线与少量静柔云。
4. 上游历史图层、CHGIS、数据数量均未修改。P4 政权渲染、后续情绪天气、雨雪闪电、鸟群与待机巡游待对应阶段；不属于本轮 P3 实现。
5. 尚无手机 GPU、4G 冷启动或完整 GPU 内存实测。已有 P2 WebGL2 要求继续适用。
6. 已完成本地提交；未推送、未部署生产站点或修改 DNS。
7. 生产构建通过，但 Vite 对按需加载的引擎分块发出 500kB 提醒（压缩前 510.11kB、gzip 130.65kB）；未调大阈值隐藏提醒。引擎继续独立懒加载。
